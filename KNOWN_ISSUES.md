# Known Issues

## 1) Legacy-файлы и миграция
- Если в `uploads/orders/**` есть папки с невалидным `orderId`, они пропускаются.
- Если для `orderId` нет записи в БД, каталог пропускается (с предупреждением в логах).

## 2) Поведение плагинов
- Плагины ограничены клиентской средой (браузер).
- При некорректном HTML/JS плагин может не стартовать, но не должен ломать основную CRM.

## 3) Ограничения вложений
- Лимиты и типы файлов зависят от параметров:
  - `fixbyte.upload.max-*`
  - `fixbyte.upload.allowed-*-extensions`
- При слишком больших файлах получите ошибку валидации на upload endpoint.

## 4) Docker/порты
- Приложение слушает порт `9087`.
- Если порт занят, контейнер/локальный запуск не поднимется.

## 5) Безопасность учетных данных
- Не храните production-пароли в репозитории.
- Используйте `.env` и защищенное хранение секретов в прод-среде.

## 6) Что делать при ошибке удаления вложения
Симптом: `No EntityManager with actual transaction available for current thread...`.

Статус: исправлено через транзакцию в `FileStorageService.deleteOrderAttachment(...)`.

Если ошибка повторяется:
1. Перезапустите приложение на актуальной версии.
2. Проверьте, что обновленный jar/образ действительно задеплоен.
3. Проверьте логи `app` контейнера.

## 7) Десктопный клиент (Electron)
- `build/icon.ico` не хранится в git — нужно запустить `node make-icon.js` при первом клонировании.
- Клиент открывает `https://crm.fix-byte.ru` — при недоступности домена показывается страница-заглушка.
- Для локального использования замените `CRM_URL` в `main.js` на `http://localhost:9087`.
- `desktop-client/dist/` и `desktop-client/node_modules/` не коммитятся (в `.gitignore`).

## 8) Канбан: ограничения вложений и превью
- Канбан принимает только изображения и текстовые файлы (`.txt`, `.md`, `.csv`, `.log`).
- Видео и бинарные форматы (например, `.pdf`, `.zip`, `.exe`) для карточек канбана не поддерживаются.
- Превью на карточке строится по первому вложению типа `IMAGE`; если изображений нет, превью не показывается.
- Лимиты по умолчанию:
  - максимум `10` файлов за один запрос;
  - изображение до `15MB`;
  - текстовый файл до `20MB`.
- Если лимит превышен или тип файла не разрешен, API возвращает ошибку валидации (`/api/kanban/cards/{cardId}/attachments`).

## 9) WARN `HandlerMappingIntrospector` при первом запросе
- Сообщения вида `Cache miss for REQUEST dispatch ... This is logged once only at WARN level` обычно появляются один раз после старта.
- Это не является критической ошибкой и само по себе не ломает работу приложения.

## 10) Рендер шаблонов после фрагментирования
- Ранее фиксировались ошибки рендера `/dashboard` и `/login` после унификации шаблонов.
- Статус: исправлено (null-safe sidebar URI + предсоздание сессии на `/login`).
- Если ошибка повторится, обновите сборку и проверьте, что запущен актуальный jar/контейнер.
